# 新增结构案例：敲敲乐

这是2026-09-16隔离候选的接入示例，不是正式发行条目，也不是可直接复制的通用合同。示例ID8.30不代表下次可用；先查当前库和历史。具体API与登记仍以当前源码为准。

## 1. 从资料到已确认的收益

本案例经确认：期限1个月；起始交易日为观察序列第1日，前5个观察日锁定，第6日起每日收盘观察，包含到期日；收盘价达到初始价105%即敲出，立即返还保证金并支付名义本金2.3%的固定收益。未敲出时，到期净收益率为max(ST/S0−1.05,−0.05)。保证金为名义本金5%，不追加，无额外费用。

这些是本例的确认结果，不能仅凭“敲敲乐”名称推导。若资料只说锁定5天，需明确起息日是否计入和第一个观察日。

手算净收益：未敲出且到期103%，收益−2%；到期100%或更低，收益−5%；有效观察日达到105%，收益+2.3%。第5个观察日达到105%仍不敲出，第6日才开始判断。本金100万元时，+2.3%净收益为23000元；返还的50000元保证金不是额外利润。

## 2. 翻译成当前字段

| 条款 | 存储键 | 公式符号或表达 | 本例存储值 |
| --- | --- | --- | --- |
| 初始参考价 | S0 | S_0 | 100 |
| 执行价 | K | K | 105 |
| 敲出价 | H_KO | H_out | 105 |
| 固定绝对收益 | r_out | r_out | 0.023，不是2.3 |
| 限损 | Lmax | ell | 0.05 |
| 保证金比例 | g | g | 0.05 |
| 锁定观察数 | Llock | n_lock | 5 |
| 观察频率 | O_KO | O_out | daily |
| 观察字段 | observation_price | 由数据需求及引擎读取 | close |

观察表达使用现有`first_time_after(S_t[O_out] >= H_out, n_lock)`。实现前检查该函数的序列计数，并用明确日期验证，不凭函数名猜测。

在OptionReg的`terms.monitor`登记tau_out；`paths`区分tau_out < inf与tau_out == inf。前者支付`cash(tau_out, N * r_out)`；后者在S_T >= K - ell * S_0时支付`cash(T, N * (S_T - K) / S_0)`，在0 <= S_T < K - ell * S_0时支付`cash(T, -N * ell)`。这些表示净收益，保证金资金流由现有金额及账本口径处理，检查是否重复计入。

本例联合约束包括K == H_out、K > S_0、g == ell和每日观察。修改敲出价时也必须处理执行价，不能让页面看似可改而提交必然失败；若页面不能联动，明确限制并按范围处理。

Core可能把合同参考本金规范为100。测试从冻结合同读取N和单位，不能拿原始请求的100万元直接除内部结果。定价字段也不能只凭名称猜单位：沿实际输出投影核对小数收益率、每100本金点值与金额。比如0.023对应2.3个百分点和100万元上的23000元；Greeks还需核对风险因子变动单位。

## 3. 接入顺序

1. OptionList登记唯一身份与顺序；OptionLib按现有产品标题格式写完整条款、手算例子、保证金及风险；OptionReg登记上述语义。三者解析后的身份和名称一致。
2. 新建同名默认JSON，从本例条款与路径经`build_payoff_input`、`render_paths`、`render_svg`等当前实际入口生成SVG；不复制近似结构图片。核对改变参数后图形是否改变。
3. 查看`model_router.py`的动态MC登记与实际适配器，确认新产品进入路由。没有解析公式就不声称解析支持。
4. 在`fair_parameter.py`逐参数登记反解能力，再核对产品汇总。当前`_derive_product_status`规则：存在supported目标则汇总supported；否则有solve_semantics_blocked则汇总该状态；全部unsupported才是valuation_only。汇总supported不代表所有参数都能反解。不得复制其他产品的证据或用“测试没跑”冒充结构永远不可解；未验证必须在交付中列为未完成，确需临时阻塞要说明原因和解除所需验证。
5. 核对`economic_conventions.py`和`metric_profile_map.py`。本例无单列期权费，采用适用的单敲出指标；实际回放检查提前终止日期、现金流和收益分母。不能只补ID而选错经济类型。
6. 通过当前构建入口生成目录与知识快照。页面检索、参数编辑、金额、推荐及报告各自验收。包内出现新产品不证明推荐已运行或报告已导出。

测试代码使用模块现有支持的导入方式。本仓库部分模块以`modules.pricer`等规范包名加载；先看实际service和已有测试的初始化，不臆造`modules.pricer.src`导入，也不为测试修改运行时导入保护。

## 4. 从最小路径到交付

先验证普通到期、锁定期内越障、第一个有效观察日越障、到期恰好触障、边界相邻值、提前支付与非法参数。再跑单点MC和Greeks、完整曲面、历史回放与金额、App操作和报告。合成交易序列可以验证事件算法，但不能证明真实交易日历、行情供应商或市场报价正确。

本例曾完成合成输入下的单点10000路径计算。此数字是测试配置，不是本Skill规定的路径数或性能承诺；今后沿用用户输入与现有精度规则。完整曲面包含大量重复估值，必须独立记录完成情况。
