# 研究报告工作区与Designer模板重构方案

状态：设计提案。已检查原生App中的报告生成、预览、编辑器和报告库，阅读Reporter、ReportEditor、Designer及HTMLDesk实现，并查看Designer五套现有示例。本提案尚未修改报告与模板实现。

## 一、产品定位

以一份持续可编辑的报告为核心组织操作：

选择分析素材 → 选择模板 → 生成报告草稿 → 编辑与组合 → 保存 → 导出。

用户操作的对象始终是一份报告。产品、模块运行结果和已有报告是素材；五套模板决定内容组织；HTML、PDF、Word是导出格式。

Reporter负责选择事实、组织内容和记录来源。Designer负责模板、组件、排版、图表样式和分页。编辑器负责用户当前正文。导出统一读取当前已保存正文，不重新计算，也不把原始结果重新填回已经修改的段落。

## 二、已发现的流程问题

| 当前证据 | 用户影响 | 重构方向 |
|---|---|---|
| 原生页面已经选择方差互换，预览仍为上一份看涨期权报告，只有一条设置变更提示 | 当前选择和正在编辑的文档身份混在一起 | 素材选择作为生成前的暂存操作；打开报告后展示明确报告名称和来源，修改素材不直接改变已打开文档 |
| 模块内有生成并保存，外层报告库还有简单报告、详细报告、参考报价三个生成按钮 | 同一操作存在两套入口和命名 | 研究报告工作区负责新建；全局报告库只负责查找、打开、导出 |
| 源选择、结果卡片、生成设置、报告库同时分列，预览在表单下面 | 正文让位于大量配置，窄窗口几乎看不到报告 | 正文居中；素材使用抽屉；左侧目录；右侧按所选内容显示设置 |
| 生成页面支持HTML、PDF，Word仅在编辑器中出现 | 用户需要为了导出Word先进入编辑流程 | 全部五类模板共用一个导出入口 |
| 当前combined生成集合索引和独立报告 | 用户可能以为会合成一份正文 | 多产品模板生成一份完整文档；分别导出属于批量导出操作 |
| 保存HTML副本、导出PDF、导出Word均通过save_edit创建新的ReportRun | 报告库出现多个看起来相同的编辑副本 | 工作文档连续保存；导出文件归属于同一报告，不生成新的报告卡片 |
| 报告库大量条目只显示详细报告；生成标题取整个source的产品名；编辑标题只更新metadata和HTML title | 列表名、正文标题、选中产品和下载名称可能不一致 | 建立唯一报告名称，默认只根据实际选中素材生成，并同步到封面、列表和导出文件 |
| 原生生成报告出现本次未运行章节；模板上下文却要求空内容块不进入交付 | 用户得到一份充满系统状态的报告 | 未选内容不生成章节；缺少用户明确要求的素材，在生成前提示具体缺项 |
| Card、Report示例以待确认占位为主；Multireport有重复小标题 | 示例不足以验证真实密度和五套模板的一致性 | 用统一、明确标注的样例素材与真实已保存结果分别验证模板，不将占位示例当正式交付 |

相关实现位置：

- modules/reporter/page/reporter.html：交付方式、内容等级、格式、独立预览与编辑器。
- modules/reporter/page/reporter.js：素材选择、默认标题、旧预览保留与多报告链接。
- products/app/frontend/optchat/optchat.js：全局报告库及编辑器入口。
- products/app/frontend/shared/app.js：报告列表的显示名称和下载链接。
- products/app/backend/report_editor.py：保存与导出耦合、标题写入及编辑副本。
- modules/reporter/src/export_service.py：combined、batch、comparison三套交付行为。
- modules/designer/src/design_renderer.py与comparison_renderer.py：五模板的实际映射和内容渲染。
- modules/designer/assets/templates与assets/themes：模板定义、HTML外壳和共享样式。

## 三、五种模板与导出格式对应

保留五个明确模板标识，界面显示一致的中文名称。

| 模板 | 界面名称 | 适用内容 | 默认组织 |
|---|---|---|---|
| card | 单产品简报 | 一个产品的精简研究材料 | 研究结论、关键条款、核心结果、主要风险 |
| report | 单产品研究报告 | 一个产品的完整研究正文或单模块专题 | 核心结论、合同与方法、已选分析、风险与限制 |
| quote | 参考报价表 | 一个或多个产品的已保存报价事实 | 按标的或篮子分组的报价表、共同条款、日期和有效性 |
| multicard | 多产品简报 | 多个产品的快速比较 | 对比摘要、紧凑产品卡、主要差异与风险 |
| multireport | 多产品研究报告 | 多个产品的完整分析与比较 | 总体结论、关键指标对比、各产品章节、统一附录 |

五种模板均可导出HTML、PDF和Word。模板不等于文件格式。

单产品与多产品的转换由素材数量给出建议，用户明确切换后生效。不要在增加素材时静默覆盖正在编辑的正文。Quote可含多个产品，不再额外派生multiquote。

研究报告不强制包含推荐结论。没有Recommender结果时，标题使用研究概览、结构说明等准确名称，不自动写出推荐、首选或优于其他结构的结论。

## 四、工作区布局

### 1. 进入模块

展示当前任务的报告，名称、模板类型、更新时间清楚可辨。提供新建报告和导入HTML两个入口。

新建报告在一个简洁面板中完成素材和模板选择。只呈现可用的分析结果，默认展示当前任务，可展开查找同一用户的其他任务结果。用户没有运行全部分析模块，也可以正常编写对应专题报告。

### 2. 打开或生成报告

顶部：报告名称、模板、保存状态、预览、导出。

左侧：文档目录和添加内容入口。目录支持跳转、重排、重命名、复制和删除章节。素材面板按需打开，不长期占一整列。

中间：报告正文占主要空间，直接编辑。提供阅读预览和分页预览，保留缩放与适合宽度。

右侧：按当前选中内容展示设置；没有选中内容时收起或显示简洁的文档设置。选择表格显示表格操作，选择图表显示图表设置，不同时堆出所有控件。

移除只有专业用户一个选项的受众下拉框；固定A4等排版规则归入分页设置，不占据生成表单。

编辑器打开时收起全局报告库。格式工具放在紧凑工具栏或选区浮层，避免工具栏占去两三行正文高度。

### 3. 文档状态

保存状态独立于分析结果是否齐全。采用保存中、已保存、未保存修改、保存失败等明确描述。

连续编辑自动保存到当前报告草稿，支持Cmd+S。网络或磁盘错误时保留本地恢复草稿。一次PDF或Word导出不新增一张报告卡片。另存副本是用户明确选择的操作。

保留原始运行结果与原始生成证据，日常界面不暴露合同版本、hash、CAS和一串内部编号。

## 五、HTML编辑与内容组合

### 1. 直接编辑

打开报告后即可修改标题、段落、列表、表格、图片、公式和图表。支持撤销、重做、查找替换、插入章节和常用格式。

复用HTMLDesk中成熟的区块选择、移动、复制、隐藏、表格、图片和图表编辑能力，保留其适用边界；文件保存、资源打包和导出使用OH自身的App服务。不要直接搬入浏览器扩展的权限和保存交互。

HTML源码作为高级入口，普通用户不需要接触。导入HTML时保留可编辑正文和可用资源，对不支持的动态组件给出具体提示，不悄悄丢失内容。

### 2. 修改数值

允许用户编辑正文、表格和图表数据。人工修改只影响报告，不修改ModuleRun，不假装完成了重新定价或回测。来源详情记录手工修改属性，普通正文不铺满审计提示。

更新分析结果时，由用户选择替换哪些内容块；已有手写分析和调整过的章节不被整篇重新生成覆盖。

### 3. 组合方式

- 同一产品：自由组合收益结构、估值、回测和人工文字，明确每项结果对应的条款、日期与区间。
- 多个产品：选择multicard或multireport，生成一份连续文档。可添加、移除、排序产品和章节。
- 已有报告：选择需要加入的章节或产品部分，归入统一目录与样式，避免直接嵌套多个完整HTML。
- 批量文件：在导出时选择分别导出，并提供ZIP下载。无需引入另一种报告类型。

报告内容组合不自动产生金融组合的加权收益或组合定价。跨产品比较须保留各自口径，不能把不同期限、日期或回报分母的数据拼成一个无说明的总指标。

## 六、Designer五模板美化

### 1. 共用设计规则

沿用OH品牌红，深蓝用于次级信息或对比系列，正文使用中性深灰。减少整段红线、彩色边框和黄色提示块。通过字号、字重、留白和对齐组织层级。

五种HTML交付提供左侧目录，简报和报价表使用紧凑可收起形式；PDF保留书签，Word保留标题层级，长文档按需生成目录。

统一标题、正文、表头、图例、数字和单位样式。正文以11至12pt为纸面起点，标题和章节形成明确字号层级，按样张复核最终取值；不以缩小正文解决内容过多。表格数字对齐、精度一致；标题不重复出现章节名、表名和同义副标题三层。

图表统一使用离线ECharts和红蓝系列。公式使用真正的数学排版。关键结论放前面；冗长方法、数据说明和详细限制移至对应附录，必要风险仍可直接找到。

报告正文使用纸面阅读主题。App深色主题包围编辑画布，不将导出文档染成整页黑色。

主题文件负责颜色、字体和共享视觉变量；模板定义决定内容组织；通用组件负责表格、图表和章节。通过模板和组件一次修改作用到五套输出，避免每套HTML再叠一份修补CSS。

### 2. card

短而完整的单产品摘要。采用清晰的产品标题、少量核心指标、关键条款和简短风险说明。以一页阅读为目标，内容超出时合理续页，不缩小字号硬塞一页。

推荐相关区块仅在实际存在推荐事实时出现。正文避免密集嵌套卡片和内部运行状态。

### 3. report

采用连续正文、左侧目录、明确章节层级和可读图表。内容按当前选中分析组织；不强制凑齐没有事实的章节。

HTML适合连续阅读；PDF使用A4分页、页码、表头重复和合理分页控制。减少正文中反复出现的摘要表、同义结论和重复风险文本。

### 4. quote

表格优先。上方简洁列出名称、日期及必要报价条件；按标的或篮子分组。同组共同条款只写一次，差异条款进入列。

宽表按业务列组排布或切换横向页面，多页重复表头。保留每项单位、报价类型和资格限制。不得把研究估计自动标成正式交易报价。

### 5. multicard

以快速比较为中心，提供统一指标摘要和短产品卡片。避免把每个产品的整套详细表格塞进一个大表格单元格。

产品较多时按组或按页续排，保留同一顺序和指标标签；不通过无限增加列或压缩字号解决。

### 6. multireport

先给总体结论与关键差异，再展开各产品详细章节。共同方法集中说明一次，产品特有条件跟随本产品。

跨产品指标表只比较能够解释清楚的字段；正文与图表优先保留可读宽度。避免从第一页到最后一页都是多列对照大表。

## 七、保存、命名和导出

报告名称只维护一个主字段，默认来自实际选中产品和模板。同步更新工作区标题、正文主标题、HTML title、报告库名称、Word文档标题和下载文件名。

示例命名：

- 中证500看涨期权研究报告
- 中证500三类结构比较
- 结构化产品参考报价表

日期、模板类型、产品数量作为列表辅助信息，不全部塞进标题。不在普通下载名称中出现manual、report_run_id等内部标识。重名下载使用系统常见序号。

前后端统一标题长度和字符规则，避免输入框接受的名称保存时被拒绝。

导出菜单：

| 格式 | 输出目标 |
|---|---|
| HTML | 可离线打开，保留可用交互图表及所需资源 |
| PDF | 以当前保存正文为准，打印分页稳定，文字可检索 |
| Word | 标题、段落、列表、表格可继续编辑；公式尽量使用原生数学对象；图表以高清图形保留，并说明交互能力差异 |

对同一报告重复导出，不重新运行研究模块，不重新生成推荐文字，不新增另一份文档。图表和公式存在格式差异时提前给出具体说明，不承诺三个格式像素级一致。

## 八、实施顺序与验收

1. 先统一五模板标识、中文名称、来源选择、主标题和保存/导出边界。
2. 把现有编辑器纳入同一报告工作区，收口重复入口和重复保存记录。
3. 实现单产品、多产品、已有章节组合及批量导出。
4. 优化Designer通用组件和五套模板，输出五套可比较样张。
5. 分别验证源码、浏览器、原生App和打包App。

新增验收文件后再按项目规则处理旧断言。重点用以下真实操作检查：

- 只选择估值结果也能生成干净的估值专题报告。
- 切换素材后，旧文档身份明确，不误以为预览已经更新。
- 同任务多产品、多次编辑和多次导出不会串用来源。
- 改名后，列表、正文和三个下载格式一致。
- 修改文字、数值、表格、公式、图表，再导出三个格式，修改均保留。
- 保存三次、分别导出三种格式，报告库仍只有一个工作文档。
- 手写内容不会因更新某个分析结果被整篇覆盖。
- multicard与multireport对多个产品生成一份实际正文，分别导出另行产生多个文件。
- 五模板分别检查短内容、长内容、宽表、复杂公式、较多产品、窄窗口和打印分页。
- 模板样张明确使用示例数据；正式报告只使用已选择的真实运行结果，二者不能混淆。

本轮先完成方案与现状审视。Reporter与Designer的产品代码、正式模板及用户报告尚未据此修改。
