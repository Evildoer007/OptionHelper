# Pricer合同估值与公平条款反解

状态：当前实现规范

日期：2026-09-04

## 1. 目标

Pricer只处理两类任务：

1. 估值：按当前合同条款、市场状态和估值时点计算尚未结算现金流的当前价值。
2. 公平条款反解：固定其他合同条款和市场状态，求一个满足产品报价方程的商业条款。

本模块不提供隐含波动率反解，也不提供波动率曲面反解。Vega和波动率风险曲线仅表示风险敏感度。

## 2. 当前输入与运行快照

任务只承载对话、运行记录和报告，不绑定产品、标的或合同。Pricer页面使用`CurrentModuleInput`，包括产品、标的、日期、合同条款、市场参数、方法和数值配置。

每次运行按当前OptionReg读取`product_id`和`rule_revision`，重新编译`ResolvedContractSnapshot`，完成合同、日期、行情和方法校验后执行。成功运行把当前输入、合同快照、数据引用、模型参数和结果写入`ModuleRun`；失败运行不产生合同状态。

再次运行、切换产品后运行以及切回原产品运行均不读取任务级活动合同，也不比较业务指纹。页面再次打开时最多恢复最近选择的产品编号，其他输入从该产品当前默认值开始。

## 3. 合同估值

设产品价值口径为`value_basis`，合同参数为\(\theta\)，市场状态为\(m\)，已观察状态为\(s\)：

\[
V=V(\theta,m,s)
\]

结果至少说明当前价值及单位、实际定价方法、估值日、合同起始日、数据覆盖、计算状态和限制。只有当前产品和方法支持时才显示Greeks与风险敏感度，空结果不占据首屏。

### 3.1 日期规则

- 新发合同默认使估值日等于合同起始日。
- 估值日早于合同起始日时阻断，并在估值日字段下显示中文业务原因。
- 估值日晚于合同起始日时按存续合同处理。
- 路径依赖产品必须取得起始日至估值日行情，并重建已观察状态。
- 修改起始日、期限或观察规则后，清除旧到期日、旧观察日程和旧路径适用性，再按当前输入生成。

### 3.2 现金流生命周期

OptionReg采用合同持有人视角，收到为正，支付为负。

- 估值日等于合同起始日：当前价值包含时点0现金流和未来现金流现值。
- 估值日晚于合同起始日：时点0现金流属于已实现现金流，不再进入当前价值。
- 当前价值只表示估值日之后尚未结算现金流的现值。
- 累计合同损益必须分别列示已实现现金流和当前价值，不能重复扣除期初期权费。

Analytical与Monte Carlo共用同一现金流时间过滤器。

### 3.3 9.3折价看涨8080期权费版

默认条款为`S0=100`、`K1=80`、`K2=100`、`alpha=80%`、`p=20%`。`p`独立可编辑，`K2=S0`由产品规则确定。

\[
CF_0=-Np
\]

\[
CF_T=\frac{N}{S_0}\left[(S_T-K_1)^+-(1-\alpha)(S_T-K_2)^+\right]
\]

合同结算收益率为\((CF_0+CF_T)/N\)：

| 到期价格 | 合同结算收益率 |
|---:|---:|
| 65 | -20% |
| 90 | -10% |
| 100 | 0% |
| 110 | 8% |

不得增加到期固定返还`N*p`。合同起始日后的估值不得再次扣除已经支付的`p`。

## 4. 公平条款反解

公平条款反解面向新发合同。固定其他条款和市场状态，仅求能力目录中登记的一个目标字段\(x\)：

\[
G(x)=V(\theta_{-x},x;m,s_{initial})-Q=0
\]

求解必须在目标合法域内进行，并使用与合同估值相同的价值口径、现金流视角和单位。

- 目标列表由当前65产品能力目录直接生成。
- 只展示产品真正支持的商业条款目标。
- 目标字段显示为“由反解求得”，其他合法条款仍可修改。
- 定价方法受目标的`allowed_methods`限制。
- 仅支持估值的产品禁用反解，并显示具体原因。
- 期限、日期、枚举、布尔值和离散观察次数不进入通用连续求根。
- 存续合同的隐含参数校准不属于公平条款反解。

能力判断直接比较当前产品规则、目标定义、完整合同输入和方法，不读取冻结证据清单，不要求手工刷新业务Hash。

反解结果使用独立结果模式：

1. 首屏显示求解条款、反解值和单位。
2. 第二层显示原值、目标合同价值、实际合同价值、残差和收敛状态。
3. 第三层显示研究估计、报价资格、数值限制和产品限制。

协议枚举转换为中文。反解模式不混入普通PV摘要、空Greeks或空风险曲面。Reporter只读取明确的`ModuleRun`及其中的当前输入、最终候选合同快照和求解事实，不读取所谓当前合同或最新合同，也不要求额外业务Hash。

## 5. 参数与单位

Pricer与Backtester共用合同参数展示协议。每个字段包含`editability`、`editability_reason`、`display_unit`、`value_encoding`、`dependency_group`和`tenor_role`。

- `editable`：独立、合法且引擎支持修改。
- `market_bound`：由本次行情冻结。
- `derived`：由其他条款和产品公式派生。
- `fixed_product_rule`：当前产品经济规则不允许独立修改。
- `internal_scale`：仅用于内部归一和计算。

不能修改的字段必须显示稳定原因，不能直接隐藏。

### 5.1 期限与观察

- `T`支持年、月、自然日输入，分别转换为`T=value`、`T=value/12`和`T=value/365`。
- 页面同时展示最终ACT/365年数。
- 修改`T`后重新生成合同到期日和观察日程。
- `T`与`n_obs`分别展示和修改；7.1与9.8不得自动合并两者。
- 观察类产品直接显示敲出、敲入、派息、触碰和重置等规则，不以“美式/欧式”替代。

### 5.2 显示单位

- 利率、票息、参与率和波动率按百分比输入，内部使用小数。
- `Pi_0`显示为“期初期权费，%”。
- `P_net`显示为“组合净期权费，%”。
- 期权费内部`5`表示`5%`，不得再次除以100。
- 标准化合同价格显示“点，S₀=100”。
- 日数、观察次数和数量分别显示“自然日”“次”“份”。
- 历史波动窗口单位为“交易日”，按最近N个交易日收益并以244个交易日年化。

## 6. 方法与数值参数

- Analytical不显示也不提交路径数和随机种子。
- Monte Carlo由用户输入路径数和随机种子。
- MC10只用于快速路由和协议测试，不构成精度门禁。
- 不设10000或100000路径发布门禁。
- 方法变化后重新计算参数可见性和适用性。

## 7. 右侧栏与错误展示

右侧栏使用无编号分组，顺序为本次任务、合同条款、市场与日期、模型与精度。普通页面不显示“固定规则与审计”、自由JSON、Task ID或Run ID；只读规则和正式输入摘要放在结果详情。

字段、单位、帮助文字、进度和错误处于正常文档流。运行进度只显示在底部运行区；日期错误显示在对应字段下方。任何状态文字不得覆盖日期值、日期图标、输入框、单位或`dt/dd`说明。内部错误码和诊断编号只放在可展开详情。

## 8. 验收

- 65产品默认估值全部经过真实Core编译。
- 每个可编辑字段至少有一个合法修改完成页面编码、Core编译和协议往返。
- 每个产品的合法缩短期限和合法延长期限均真实执行，不允许用跳过代替。
- 1.1覆盖标的、估值日、合同起始日、期限、执行价和期初期权费。
- 雪球覆盖标的、期限、票息、敲入敲出障碍、观察频率和日程重建。
- 7.1与9.8分别改变`T`和`n_obs`。
- Analytical请求不含路径数或随机种子，Monte Carlo可按用户输入运行。
- 9.3按4个价格场景逐笔复算，并验证`p`独立修改和存续期现金流。
- 同一任务完成A产品、B产品、A产品以及同一输入连续两次运行。
- 浏览器、原生App和最终打包App分别记录证据。

## 9. 明确禁止

- 任务级活动合同、合同方案或合同版本选择器。
- 以产品、标的、合同或数据资产限制任务自由切换。
- 用业务Hash、合同指纹或冻结清单阻止当前输入运行。
- 为兼容旧协议继续输出旧合同或旧收益字段。
- 为了通过测试保留错误文案或跳过合法期限场景。
- 把Vega或波动率风险图称为隐含波动率反解。
- 在存续期估值中重复扣除已支付期权费。
