# Reporter模块指南

## 职责

显式选择兼容的ModuleRunRef、产品资料与研究证据，冻结为ReportUnit或ReportBundle，再交给Designer输出研究简报、完整研究报告或参考报价的HTML或PDF。

## 规则

- 不扫描“最新结果”，不接收任意物理结果路径。
- 不重算Payoffer、Pricer或Backtester，不用默认资产或示例替代本次结果。
- 一个ContractReportUnit只对应一个合同和一组有序标的；研究简报和完整研究报告的多候选使用Bundle或比较总览。参考报价可以按本次明确选择的多个合同或运行结果分组汇总。
- 内部`card`对应研究简报，固定逐字呈现结构推荐、推荐理由、关键合同条款、估值摘要、回测摘要、主要风险；不渲染损益图、收益情景图或目录。
- 内部`report`对应完整研究报告，固定逐字呈现核心结论、结构推荐、合同参数、收益结构、估值定价、历史回测、风险提示，采用连续A4正文；宽屏HTML提供左侧七章目录，PDF不显示目录。
- 内部`quote`对应参考报价。调用方提供本次推荐后新完成或后续复用的Payoff、Pricing或Backtest运行；Reporter从每条运行的合同快照整理合同条款表，不重跑计算、不接受手写报价JSON。同一候选的同一合同快照只保留一行，不同参数版本保留多行；同一单标的按真实`asset_id`汇入同一张表，多标的结构按完整标的组合单列一组。Quote只展示合同条款，不把估值、回测或模型文本推断为报价，也不渲染图表。
- HTML和PDF只是交付格式；用户未指定时默认HTML。不得为了确认默认格式或目录新增一轮对话。
- ResultStorePort和Designer ModulePort均由宿主注入；Reporter不导入Designer内部渲染器，也不接受结果目录。
- 页面通过宿主注入的`ResultSelectionPort`列举当前租户已授权的报告来源；它只返回脱敏候选、ModuleRunRef及合同摘要，页面不能扫描ResultStore或输入物理路径。
- 页面提交的是来源ID、候选、模块和交付选项；服务端重建正式ReportRequest、再次通过ResultStore校验，再提供仅限`run_manifest.json`声明文件的预览和下载。
- 正式预览与下载只经过App ReportRun白名单和principal、audience、task授权；独立HTTP Host默认禁用，仅可在显式开发模式、回环地址和三个受控端口均已注入时启动。
- `config.py`只保存Reporter的输出目录、请求大小和PDF头校验默认值，并由服务入口和产物校验器实际使用。
- `artifact_validator.py`是报告产物的唯一校验器：受控相对路径、普通文件、SHA-256、Designer返回契约和PDF文件头均由它验证。
- 当前Designer每次渲染一个完整合同payload；研究简报和完整研究报告的`combined`与`batch`明确交付为组合索引加候选独立报告，不伪称为同页多合同细节页。参考报价则使用单一分组报价表交付本次明确选择的多个结构。
- 报告不包含审计章节、系统品牌、工具名、运行标识、物理路径或内部字段。首次交付时，Reporter冻结研究事实并保存`designer-input.json`。同一份冻结输入后续补Card、补Report或转换HTML/PDF时，直接交给Designer重新渲染，不重跑模型、取数、定价、回测，也不重新编排金融事实。新的参考报价或新的结构组合，由Reporter依据本次明确选择的已保存运行结果及其合同参数重新冻结，但同样不重跑计算。
- 新的交付事实组合只能按“Reporter→Designer”链路生成：Reporter冻结事实，Designer完成渲染。HTML成品不是下一份交付的事实来源，不能反向提取为Card或Quote。Reporter或Designer不可用时，明确返回报告能力不可用及缺失条件，不得自行编写Python、拼接HTML或调用其他临时渲染方式替代。
- 对话Host可以提出研究结论和选择交付类型，但不得直接写报告文件。只要用户要求研究简报、完整研究报告或参考报价，Reporter就是唯一事实编排入口；未要求交付时不调用Reporter。
- 基于当前任务已验证ModuleRunRef生成交付物时不重新取数或重算，也不重新打开首次配置门禁。缺少模块只影响覆盖状态；除非用户另行要求补算，不得为了填满章节触发数据请求。
- 交付形式与覆盖状态分开：`complete`表示本次用户要求的全部模块均已验证；`partial`表示只交付现有事实并明确缺失及影响；`unavailable`表示事实或渲染能力不足，不能生成替代文件。
- 研究简报固定顺序为结构推荐、推荐理由、关键合同条款、估值摘要、回测摘要、主要风险；无章节目录、无损益图，HTML固定210mm宽度、高度随完整内容自然延展，不保留空白占位。完整研究报告固定顺序为核心结论、结构推荐、合同参数、收益结构、估值定价、历史回测、风险提示；固定连续A4正文，宽屏HTML提供左侧七章目录，PDF不显示目录，HTML和PDF均按A4自然分页。参考报价固定为按真实挂钩标的分组的报价表：同一单标的使用同一张表，多标的结构按完整标的组合单列一组；每张表的列是已选合同条款的并集，不适用条款显示`—`。Quote不展示损益图、估值图或回测图。复杂结构不因版面长度被拒绝。七个Report标题和六个Card标题的顺序均是交付契约，Reporter不得替换、合并、删除或重排。
- 具备正式Reporter和Designer端口的Host可生成HTML或PDF并支持两份交付。项目级独立CLI当前只支持单份HTML；不支持的格式或组合必须明确返回不可用，不得静默降级或手工补写。
- 面向用户的估值、回测和报告只展示百分比。`S0Raw`仅用于真实价格与标准化合同换算，不作为面向用户字段；内部现金流、点数、金额和名义本金不得投影到页面、正式Tool、CSV或报告。

## 输出

写入安装目录之外的项目Store中的`$OPTIONHELPER_RESULT_ROOT/output_report/{task_id}/{report_run_id}/`；默认根目录为当前项目的`./result`。至少保存冻结事实、渲染输入、产物与运行清单。

## 用户可见进度

以下文案直接面向用户，不包含Tool名、JSON字段、运行标识、环境名称或物理路径。开始提示一次；事实编排和交付校验明显耗时时才发送进度，进度最多更新1至2次，不要求用户回复，完成后直接给结果。

正式交付中Reporter作为报告阶段的进度所有者；Designer不再重复发送开始或完成提示。

- 开始：我先核对已验证的研究结果，再整理报告事实和章节结构。
- 进度：报告内容已经整理，正在生成交付文件并检查完整性。
- 完成：报告已经生成并通过完整性检查。下面给出核心结论和交付文件。
- 失败：当前无法完成正式报告。我会说明缺少的结果或渲染能力，不自行编写脚本或HTML代替。
