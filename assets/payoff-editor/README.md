# Payoff SVG Editor

本工具用于为OptionHelper中的期权与结构化产品制作情景Payoff SVG。每个产品对应一张正式SVG；产品名称、情景数量、情景顺序和子图标题均由资料库锁定，人工与大模型只能调整图形参数。

## 交付给他人时如何打开

将完整OptionHelper项目发送给对方，但不得包含`evals/model_config.json`、`evals/model_results/`、`.DS_Store`或`__pycache__/`等本机文件。对方只需进入`assets/payoff-editor/`，按系统双击以下文件：

- macOS：`payoff-editor-starter.command`
- Windows：`payoff-editor-starter.bat`

Starter会自动检查项目目录、Node.js版本和4179端口，然后启动服务并打开浏览器。若编辑器已在运行，再次双击Starter会直接重新打开网页；无需Python、Conda、npm安装、终端命令或联网。

唯一系统前提是对方电脑已安装Node.js 18或更高版本。若未安装、版本过低、端口被占用或项目目录不完整，Starter会显示明确原因。

适用对象：

- 人工通过网页创建、编辑、保存和发布Payoff图。
- 大模型直接修改草稿JSON，完成校验和临时渲染。
- 正式SVG必须由人工在网页内确认发布。

## 1. 先理解文件与职责

```text
OptionHelper/
├── references/
│   ├── optionlist.md                 产品名称与编号的唯一来源
│   └── optionlib.md                  损益结构表与情景的唯一来源
├── assets/payoff/                    已人工确认的正式SVG
└── assets/payoff-editor/
    ├── app/                          网页、服务端与命令行程序
    ├── payoff-editor-starter.command macOS双击启动入口
    ├── payoff-editor-starter.bat     Windows双击启动入口
    ├── state/                        当前草稿JSON
    │   └── history/                  重建或覆盖前的历史备份
    ├── templates/template.svg        视觉参考模板，不参与生成
    ├── tests/                        自动测试
    ├── README.md
    └── package.json
```

`payoff-editor`可以随完整OptionHelper项目迁移，但不能脱离项目根目录单独运行。它必须读取`references/optionlist.md`、`references/optionlib.md`；首次确认发布时，缺失的`assets/payoff/`会自动创建。

## 2. 资料库前提

一个产品可以创建Payoff图，必须同时满足以下条件：

1. `optionlist.md`中存在唯一的产品编号和中文名称。
2. `optionlib.md`中存在同编号、同名称的三级标题，例如`### 3.2 牛市看跌价差`。
3. 对应的`#### {编号}.2 损益结构`中存在有效Markdown表。
4. 表头前两列必须依次为`情景`、`判断条件`，并至少有一列名称包含`净损益`。

推荐的损益结构表：

```md
| 情景 | 判断条件 | 持有方净损益 |
| --- | --- | --- |
| 到期不低于高行权价 | $S_T\ge K_2$ | $C$ |
```

`情景`列每一行对应一张子图。`.2 损益结构`的公式、判断条件和区间是默认曲线的唯一几何来源；同一产品的`.3 示例`仅用于读取参数、校验金额与补充可验证的离散路径结果。编辑器不会按示例表行序连线，也不会将示例表文字写入正式SVG。

## 3. 启动方式

前提：安装Node.js 18或更高版本。不需要Python、Conda、npm安装、终端命令或联网。

### macOS

双击：

```text
assets/payoff-editor/payoff-editor-starter.command
```

### Windows

双击：

```text
assets\payoff-editor\payoff-editor-starter.bat
```

启动器会检查完整项目结构、Node.js 18或更高版本和4179端口，等待服务就绪后自动打开浏览器。若编辑器已在运行，再次双击会直接重新打开网页；若检查失败，按提示处理即可；不需要运行任何命令。

以下命令仅供开发维护使用，普通使用者不需要执行：

```bash
node assets/payoff-editor/app/server.mjs
```

浏览器地址：`http://127.0.0.1:4179`。

## 4. 人工网页操作

### 4.1 从模板新建

1. 在左侧选择产品。
2. 页面立即展示资料库中的情景数量、顺序和标题。
3. 点击“从模板新建”。
4. 点击“进入编辑”后可绘制或设置各情景子图；再次点击同一按钮即可“退出编辑”。
5. 点击“保存草稿”。
6. 任意编辑阶段都可点击“确认发布”。网页会先展示发布前审阅，列出每个情景是否已绘制、关键价格线和辅助线数量、与当前正式SVG的差异及覆盖范围；人工核对后点击“确认发布”。发布不改变`optionlist.md`状态；仅在满足`optionlib-manager.md`的正文、图示、定价资源与一致性条件后，才可改为“已录入”。

“从模板新建”只创建浏览器内的未保存配置，不会自动生成或改写JSON。页面出现“未保存修改”时，代表当前修改尚未写入文件。

### 4.2 打开现有草稿

选择产品后，编辑器会检测`state/`中是否已有匹配草稿。若存在，“打开现有草稿”按钮可用。

- 打开现有草稿只读取JSON，不会改写文件。
- 打开后默认是预览锁定；点击“进入编辑”即可修改图形，再次点击会退出编辑并回到预览锁定。
- 若当前页面有未保存修改，切换产品、打开其他草稿、导入SVG或关闭网页都会要求确认，避免静默丢失修改。

### 4.3 保存草稿与正式发布

| 动作 | 写入位置 | 是否覆盖 | 是否需要确认 |
| --- | --- | --- | --- |
| 保存草稿 | `state/{编号}_{名称}.payoff.json` | 更新当前草稿 | 模板图覆盖已有草稿时确认 |
| 确认发布 | 当前草稿JSON与`assets/payoff/{编号}_{名称}_payoff.svg` | 覆盖正式SVG | 必须人工二次确认 |

发布不设置曲线完成度门槛。未完成曲线会作为SVG中的待补充状态保留；仅资料库快照时效提示不阻止人工确认。图形结构、类型、范围、精度和锁定字段校验必须通过，防止错误数据写入正式SVG。`optionlist.md`中的入库情况不作为发布条件；正式SVG发布后仍须满足定价资源和一致性要求，才可维护为“已录入”。发布时会先生成新文件；新文件可写入后才以原子替换覆盖正式SVG，并保留旧版本于`state/history/`。

不要直接调用本地`/api/publish`接口或以脚本模拟发布确认。正式发布应只通过网页“确认发布”完成。

## 5. 草稿、历史记录与正式SVG

| 文件类型 | 位置 | 用途 | 何时生成 |
| --- | --- | --- | --- |
| 当前草稿 | `state/{编号}_{名称}.payoff.json` | 人工和大模型的唯一编辑源 | 点击“保存草稿”或正式发布时 |
| 历史备份 | `state/history/` | 保存被替换的旧版本，供追溯 | 重新导入情景或覆盖正式SVG时 |
| 正式SVG | `assets/payoff/{编号}_{名称}_payoff.svg` | 对外使用的正式图片 | 人工确认发布时；目录缺失则自动创建 |

历史记录不是自动保存，也不是每次编辑的版本快照。它只在会替换已有内容的关键动作前生成备份。

旧版v1草稿或原生SVG在加载时会在内存中迁移为v2真实坐标；打开不改写原文件，首次保存或发布才写入v2。

## 6. 可以调整与不能调整的内容

### 可以调整

- 曲线类型：折线或阶梯线。
- 每图独立设置X轴价格范围和Y轴净损益范围。
- 曲线节点：标的价格(%)与净损益，每图2至12个节点。可在后一节点勾选“断”形成不连线的跳变，并以`○`表示不含端点、`●`表示包含端点。
- 曲线线宽：0.10至20.00px。
- 线条规范固定，不能在网页或JSON中改色：Payoff为光大红`#C8102E`实线，坐标轴为深灰`#252525`；`S₀`为灰色；所有执行价`K`族为蓝色`#1F5FA8`；所有障碍、避险、缓冲及限损价为金黄色`#D89B27`；局部辅助线为中性灰`#8A949E`虚线。
- 标准关键价格线：真实价格坐标，每图最多5条。它们以坐标轴旁的短标记显示，并标出名称、数学符号和数值；局部辅助线仅作局部几何参照，直接标数值而不进入图例。
- 局部辅助线：真实坐标的非语义画图线段，每图最多6条，可选横向或纵向，样式固定为虚线，并可单独设置起点和终点。图内拖动圆点移动线段位置，拖动两端小圆点调整线段长度。
- 编辑模式下可重置当前情景或整张图；两项操作均须确认，且恢复默认坐标范围并清空曲线、关键价格线和辅助线，不改资料库绑定。
- 画布预览缩放，以及左右面板宽度。
- 自动取景：按曲线节点、关键价格和辅助线重新计算坐标范围，保留留白并令资料库定义的X参考值与Y=0居中；不修改曲线或关键价格。

### 不可以调整

- 产品名称、编号、SVG文件名。
- 情景数量、顺序、标题、判断条件和净损益文字。
- 图例、字体、颜色、固定1500px画布宽度和双列布局。
- 任意自由文字、图片、外链资源或自定义SVG元素。

## 7. 绘图规则

- 每张SVG固定1500px宽，情景卡片双列排列；总高度随情景行数增加。
- 每张卡片468px高，绘图区642×356px；情景标题始终单行显示，过长时压缩排版但不截断。
- X轴默认是标的价格(%)，Y轴为净损益原始数值。方差互换例外，X轴为已实现波动率σ，参考值为执行波动率13；区间计息例外，X轴为区间内观察日数P，参考值为11天；DCN和保底DCN例外，X轴为满足计息条件次数n_c，参考值为6次。横轴变量、单位及参考值由资料库快照锁定，不能由人工或模型改写。
- 十字轴固定表示纵轴`X=参考值`、横轴`Y=0`，由范围自动定位，不能拖动。价格图的参考值为100%，方差互换为13，区间计息为11天，DCN为6次；X范围必须严格包含参考值，Y范围必须严格包含0。
- 当`K`是唯一的执行价且等于当前参考值时，该记录保留在JSON中，但不另画蓝线也不列入图例，即使同图还有障碍价；其他执行价、障碍价和期初价正常显示。
- 曲线节点、关键价格线和局部辅助线都使用真实数值坐标，必须落在对应范围内，最多两位小数。默认曲线先按`.2 损益结构`的公式和条件区间生成，再使用`.3 示例`中的千分位金额、负号、中文金额单位、结算价、期末价、触及价和波动率校验。路径型示例只显示可确认的离散点，绝不把不同路径样本连成收益线；若资料库不足以确定真实横轴位置或数值，子图明确保留为“待绘制”，绝不补造坐标。跳变使用同价的相邻两节点表达，后一节点写`breakBefore:true`以断开曲线；端点可写`endpoint:"open"`或`endpoint:"closed"`。图内不显示Y轴范围文字；关键价格在坐标轴旁显示名称、符号和数值，局部辅助线在图内显示自身数值。
- 参考值标签与纵轴错开，纵轴顶部和横轴右端带箭头。
- 画布缩放范围为1%至400%；加减按钮和Ctrl/Command加滚轮均按1%变化，只影响浏览器预览，不影响导出SVG。
- 使用中键拖拽，或按住空格后以左键拖拽，可平移画布查看放大后的区域；这不会改动图形或导出SVG。
- 左侧和图形控制中的判断条件会离线渲染常见LaTex内联公式，包括上下标、`\le`、`\ge`和`\cdot`；资料库原文与导出SVG均不改写。
- 左右面板宽度仅在当前网页会话有效，刷新后恢复默认。

## 8. 资料库变更与“重新导入情景”

如果你修改了`optionlib.md`中的损益结构表，例如增加、删除、改名或调整情景顺序，原草稿会与资料库不一致。此时编辑器会锁定编辑和保存，并清晰提示资料库错配；正式发布仍可由人工在审阅后确认。

正确处理程序：

1. 先在`optionlib.md`确认产品编号、名称和`情景`列正确。
2. 回到编辑器，点击“重新检测资料库”。
3. 确认提示无误后，点击“按资料库重新导入情景”。
4. 阅读归档确认提示并确认。
5. 编辑器将旧草稿移动至`state/history/`，按最新情景生成空子图。
6. 重新绘制曲线，再保存或发布。

重新导入不会自动把旧曲线映射到新情景。情景的经济含义、数量或顺序发生变化时，必须重新判断并绘制。

## 9. 外部SVG规则

可以拖入或选择SVG文件。

- 原生SVG：内嵌Payoff JSON、资料库绑定有效，且与本地草稿JSON完全一致时，可恢复为可编辑图。
- 非原生SVG或任一绑定不一致：仅只读预览，不能保存、发布或反向编辑。

不要手工修改正式SVG文本后再导入。若要修改图形，应打开对应草稿JSON或从网页选择产品后打开现有草稿。

## 10. 大模型JSON操作规则

大模型只允许读写：

```text
assets/payoff-editor/state/{编号}_{名称}.payoff.json
```

只允许修改每个`graphics`元素中的以下字段：

```text
curve
scale
thresholds
guides
```

`scale`必须为`{xMin,xMax,yMin,yMax}`；曲线节点使用`{x,y}`真实数值，可选`breakBefore:true`和`endpoint:"open"|"closed"`。`breakBefore`表示从该节点起不连接前一段曲线；相同X值的折线节点只有在后一节点使用该字段时才有效。关键价格线使用`{token,value}`，可用`S₀`、`K`、`K₁`至`K₄`、`K_p/K_c/K_u/K_d`、`H`、`H_out/H_{out,2}/H_{out,t}`、`H_in/H_{in,2}`、`H_c/H_buffer/H_floor/H_reset/H_u/H_d`、`H_{hedge,1}/H_{hedge,2}`、`B`、`L`，不允许自由文字、颜色或线型。执行价族统一为蓝色，障碍、避险、缓冲及限损价统一为金黄色，期初价为灰色；导出图中以轴旁短标记和“名称+符号+数值”呈现，不与局部辅助线混淆。局部辅助线使用`{direction,value,start,end,style}`：横线的`value`为Y位置、`start/end`为X起止；纵线的`value`为X位置、`start/end`为Y起止。它是无语义的中性灰虚线，并在图内只标示自身数值。新草稿的`style`固定写为`dashed`；旧JSON中的`solid`加载后自动规范为`dashed`。`start/end`可以同时省略，兼容旧草稿并按当前坐标范围绘制全跨度线；首次修改端点时会自动补齐两端。结构预校验文件为`schema/optionhelper-payoff.v2.json`，发布仍以`validateConfig`为准。`library.axis`是只读资料库配置，v1中的`axis`、归一化节点、`threshold.x`和`guide.position`仅用于加载时迁移，不应再写入新草稿。

禁止修改：`$schema`、`schemaVersion`、`library`、`scenarioId`、产品名称、情景文字、子图数量与顺序。

修改后必须校验：

```bash
node assets/payoff-editor/app/cli.mjs validate --input assets/payoff-editor/state/3.2_牛市看跌价差.payoff.json
```

如需临时渲染供检查：

```bash
node assets/payoff-editor/app/cli.mjs render \
  --input assets/payoff-editor/state/3.2_牛市看跌价差.payoff.json \
  --output /tmp/3.2_payoff.svg
```

命令行只能生成临时SVG，不能写入`assets/payoff/`。正式发布仍需人工回到网页点击“确认发布”。

## 11. 常见问题

### 为什么我没有点保存，`state/`里却已有草稿？

当前版本不会自动保存。已有草稿通常来自此前点击保存、命令行写入，或旧版本编辑器曾自动创建的草稿。打开已有草稿本身不会改写该文件。

### 没做完图，关闭网页会怎样？

已保存内容保留，未保存修改丢失。关闭前网页会提示确认；如需继续，请先点击“保存草稿”。

### 为什么不能编辑或发布？

通常是资料库不一致、情景数量或标题被改动、数值超出范围，或外部SVG不含有效内嵌JSON。先阅读页面提示，再修改资料库或草稿JSON；资料库提示和待绘制曲线不阻止人工确认发布。

### 为什么“打开现有草稿”不可用？

该产品在`state/`中尚无已保存草稿，或编辑器仍在检测草稿。可先从模板新建，完成后保存草稿。

### 如何运行自动测试？

```bash
cd assets/payoff-editor
npm test
```

测试只检查逻辑与输出，不会发布正式SVG，也不会修改现有草稿。

## 12. 迁移与维护注意事项

- 迁移时复制完整OptionHelper项目，保留`references/`、`assets/payoff/`和`assets/payoff-editor/`的相对路径。
- 不要移动或重命名`state/`中的文件；文件名与产品编号、中文名称绑定。
- 不要手工清空`state/history/`，除非确认不再需要历史追溯。
- 不要把临时渲染SVG、截图或外部文件混入`assets/payoff/`；该目录只放人工确认后的正式SVG。
- 资料库先于Payoff图存在。新增产品时，应先维护`optionlist.md`和`optionlib.md`，再创建Payoff草稿。

更完整的资料库绑定与发布规范见`references/payoff-manager.md`。
