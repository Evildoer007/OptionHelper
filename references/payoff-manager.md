# Payoff SVG编辑与发布规范

本规范定义OptionHelper中Payoff SVG的资料来源、人工编辑、模型JSON修改、发布和错配处理。目标是每个产品一张正式SVG，图中文字与资料库严格一致。

## 1. 资料库前提

产品必须同时满足以下条件，才可创建或编辑Payoff图：

1. `references/optionlist.md`中存在唯一的“标题编号（兼容旧版分类编号）＋中文唯一名称”。
2. `references/optionlib.md`中存在完全相同的三级标题`### {标题编号} {中文唯一名称}`。
3. 产品的`#### {标题编号}.2 损益结构`中存在Markdown表，首列名必须严格为`情景`，不接受“情形”“情形或判断条件”等同义名称，并至少有一列名称包含“净损益”。
4. `optionlist.md`中的入库情况仅反映资料库维护进度，不是Payoff发布条件。应在正式SVG发布后，再将产品更新为“已录入”。

推荐表头：

```md
| 情景 | 判断条件 | 持有方净损益 |
| --- | --- | --- |
```

`情景`列的每一行对应一个子图，行顺序即子图顺序。`.2 损益结构`中的公式、判断条件和区间决定默认曲线；`.3 示例`只用于参数、金额和已知离散路径结果的校验，绝不按示例表行序连线。示例表文字不会写入正式SVG。

## 2. 文件关系

| 位置 | 内容 |
| --- | --- |
| `assets/payoff-editor/templates/template.svg` | 唯一视觉参考模板，不参与产品生成 |
| `assets/payoff/{编号}_{名称}_payoff.svg` | 已人工确认的正式SVG；目录在首次发布时自动创建 |
| `assets/payoff-editor/state/{编号}_{名称}.payoff.json` | 当前编辑JSON，也是模型唯一可编辑源 |
| `assets/payoff-editor/state/history/` | 被替换的正式SVG与重新导入前的编辑JSON |

正式文件名、SVG标题条和JSON中的产品绑定均从`optionlist.md`生成。产品名称不能在编辑器、JSON或SVG中手动改写。

## 3. 人工操作程序

1. 维护`optionlist.md`与`optionlib.md`，确认损益结构表已包含`情景`列。
2. 启动网页，在“产品与情景”中选择产品。左侧立即展示来自资料库的情景、数量和顺序。
3. 如需从零开始，点击“从模板新建”；如需继续已保存的工作，点击“打开现有草稿”。模板图只存在于浏览器内，点击“保存草稿”前不会创建或改写JSON。
4. 默认是预览锁定。点击“进入编辑”后可拖动或设置图形元素；再次点击同一按钮退出编辑并回到预览锁定。
5. 点击“保存草稿”保存编辑JSON；若模板图将覆盖已有草稿，网页会先确认。任意编辑阶段均可点击“确认发布”；网页先展示发布前审阅，逐情景列出曲线完成情况、关键价格线和辅助线数量、与当前正式SVG的差异及覆盖范围。未完成曲线会保留为待补充状态。人工二次确认后，系统归档旧版本并覆盖正式SVG，随后再维护`optionlist.md`的入库情况。

存在未保存修改时，切换产品、导入SVG、重新打开草稿或关闭页面都会要求确认，不会静默丢弃浏览器内修改。

允许调整：每图的X/Y坐标范围、折线/阶梯线、真实坐标曲线节点、曲线粗细、标准关键价格线，以及最多6条横向或纵向局部辅助线。曲线节点支持“断开前段”以及`○`不含、`●`包含端点，用同价相邻节点表达跳变支付。网页提供“自动取景”，按节点、关键价格和辅助线留白并将资料库定义的X参考值与Y=0居中，不改图形数值。颜色和线型均固定：Payoff为光大红`#C8102E`实线，坐标轴为深灰`#252525`；`S₀`灰色，K家族分别使用不重复蓝色，`H_out`金色，`H_{out,2}`深琥珀色，`H_{out,t}`褐金色，`H_in/H_{in,2}`使用两种青绿，`H_c/H_buffer/H_floor/H_reset/H_u/H_d/H`均使用不重复固定色；辅助线1至6使用固定不重复的低饱和色。除Payoff外所有线均为虚线。图内不放关键价格注释文字，名称、数学符号和数值统一在SVG底部图例显示。局部辅助线只用于辅助绘图，可设置位置、起点和终点，不显示自由文字。编辑模式可在确认后重置当前情景或整张图；重置恢复默认坐标范围并清空图形元素，不改资料库绑定、情景标题、条件、顺序或数量。网页会将判断条件中的常见LaTex内联公式离线渲染为可读数学排版，但不改写资料库原文。

不得调整：产品名称、SVG文件名、情景数量、情景顺序、情景标题、任意图中文字、字体、颜色、图例、画布宽度、两列布局、自由图片和任意SVG元素。

画布宽度固定1500px，始终双列；基础高度为`max(636,156 + 480×ceil(情景数/2))px`，底部图例超过一行时每增加一行追加28px。每张情景卡片468px高，标题严格单行，绘图区642×356px；超长标题完整保留并压缩到单行。X轴默认是标的价格(%)，Y轴为净损益原始数值；方差互换的X轴是已实现波动率σ，参考值为执行波动率13；区间计息的X轴是区间内观察日数P，参考值为11天；DCN和保底DCN的X轴是满足计息条件次数n_c，参考值为6次。横轴变量、单位和参考值由`library.axis`锁定，旧JSON加载时补齐默认价格轴。十字轴固定表示X=参考值和Y=0，并按范围自动定位，不能拖动；X范围必须严格包含参考值，Y范围必须严格包含0。图内不显示`Y:`范围文字。若`K`是唯一执行价且等于当前参考值，该记录保留在JSON中但不另画关键价格线或底部图例，即使同图还有障碍价。曲线节点、关键价格线和局部辅助线均使用真实坐标，均需落在对应范围内。默认曲线先按`.2 损益结构`的公式和条件区间生成，再使用`.3 示例`中的金额、终值和路径信息校验；不同路径的离散样本必须断开显示，绝不连成收益线。资料库不足以确定真实横轴位置或数值时，子图保留“待绘制”，禁止使用任意临时坐标。折线相同X值的相邻节点仅在后一节点`breakBefore:true`时表示跳变，`endpoint`可为`open`或`closed`。曲线每图2至12个节点、线宽0.10至20.00px，关键价格线每图最多4条，局部辅助线每图最多6条，所有图形数值最多两位小数。局部辅助线是有限线段：横线的`value`是Y位置、`start/end`是X起止；纵线反之。旧JSON可省略`start/end`并自动绘制为全跨度线。网页缩放可输入1%至400%，加减及Ctrl/Command＋滚轮均按1%变化，只影响预览，不改变导出SVG尺寸；中键拖拽或按住空格后左键拖拽可平移画布，不改变图形或导出结果。左右面板可在本次会话中拖动调宽。

## 4. 资料库错配

下列情况停止编辑与保存，仅保留预览；正式发布可由人工在审阅后确认：

- `optionlist.md`没有目标产品；
- `optionlib.md`没有同编号同名称的产品章节；
- 损益结构表缺失、没有`情景`列、情景行为空；
- 草稿JSON的产品或情景快照与当前资料库不同；
- 子图数量、顺序或标题不再与`情景`列一一对应。

“待录入”不影响创建、保存或正式发布。完成正式SVG发布后，再更新目录状态即可。

页面必须显示明确提示，例如：

> 当前图的情景与optionlib.md不一致。请修改`#### 8.5.2 损益结构`中的“情景”列后重新导入情景。

此时不能在编辑器中改标题或增删子图。应先修改`optionlib.md`，再重新检测并点击“按资料库重新导入情景”。网页会明确提示该操作将归档旧编辑JSON；确认后系统才将其移入`assets/payoff-editor/state/history/`，再按最新情景重建空子图，不自动将旧曲线映射到新情景。

## 5. 大模型JSON程序

模型直接读取和修改`assets/payoff-editor/state/`中的JSON，只能改`graphics`下的图形字段：`scale`、`curve`、标准`thresholds`和`guides`。JSON必须是`optionhelper-payoff/v2`；每图`scale`为`{xMin,xMax,yMin,yMax}`，默认`{0,200,-100,100}`。X是由`library.axis`指定的实际结算变量，Y是净损益原始数值；范围必须严格覆盖该变量的参考值和Y=0。曲线节点使用`{x,y}`，可选`breakBefore:true`和`endpoint:"open"|"closed"`；相同X值的折线节点只有在后一节点使用`breakBefore:true`时才有效。关键线使用`{token,value}`，局部辅助线使用`{direction,value,start,end,style}`，均为真实数值且最多两位小数。横线的`value`为Y位置，`start/end`为X起止；纵线相反。新JSON的`guides.style`固定为`dashed`，旧JSON的`solid`会在加载时转为`dashed`。兼容旧草稿时可同时省略`start/end`，此时按全跨度绘制。`strokeWidth`为0.10至20.00。关键线只使用标准符号：`S₀`、`K`、`K₁`至`K₄`、`K_p/K_c/K_u/K_d`、`H`、`H_in/H_{in,2}`、`H_out/H_{out,2}/H_{out,t}`、`H_c/H_buffer/H_floor/H_reset/H_u/H_d`，不允许自由文字、颜色或线型。`guides`仅允许`horizontal`或`vertical`，不允许自由文字、颜色或线型。v1中的`axis`、归一化节点、`threshold.x`和`guide.position`会在加载时迁移为v2；首次保存或发布才写回v2。`library`对象及其`axis`是只读资料库快照；任何改写都会被校验器拒绝。

```bash
node assets/payoff-editor/app/cli.mjs new --product 8.5 --output assets/payoff-editor/state/8.5_经典型雪球.payoff.json
node assets/payoff-editor/app/cli.mjs validate --input assets/payoff-editor/state/8.5_经典型雪球.payoff.json
node assets/payoff-editor/app/cli.mjs render --input assets/payoff-editor/state/8.5_经典型雪球.payoff.json --output /tmp/8.5_payoff.svg
```

命令行只能生成临时SVG，不能写入正式SVG目录。正式发布必须回到网页点击“确认发布”。

## 6. 外部SVG

拖入或选择SVG时，系统检测内嵌JSON、资料库绑定和匹配的本地草稿JSON。

- 三项全部匹配：可按对应产品打开，仍默认预览锁定。
- 任一不匹配：外部SVG只读预览，不允许保存、发布或反向编辑。

SVG必须是纯矢量、无外链资源、无嵌入位图，并采用光大红`#C8102E`、金橙`#D89B27`、深灰坐标轴和内嵌图例。交付目标小于25KB。
